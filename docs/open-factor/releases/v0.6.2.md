# Open Factor 0.6.2

Small responses that make logging feel connected: purposeful onboarding motion, tactile controls and clear set completion.

## Changes

- The first onboarding page settles in as the progress rail fills. Existing drafts open already settled, including a return from Health Connect. Nothing waits for the animation to finish before accepting input.
- Setup steps move briefly in the direction of navigation while the header and primary action stay anchored. The progress rail follows the durable setup stage.
- Primary actions, round actions, the quick-action button and set-completion controls respond subtly to a touch. Their native ripple, cancellation, keyboard activation and touch bounds remain intact.
- A completed set transitions into its existing green state with a small check response. One gentle native haptic acknowledges a successful saved set, Log all sets action or completed onboarding. Invalid inputs, undo and restored completed sets do not trigger it.
- Android's Remove animations/animator setting is observed while the app is open and on return. The new effects and existing navigation pill/drift/icon motion settle immediately when disabled. State and feedback remain visible.

## Review

The pass follows [Emil Kowalski's interaction guidance](https://github.com/emilkowalski/skills/blob/main/skills/emil-design-eng/SKILL.md), translated into the app's existing native Compose system.

| Before | After | Why |
| --- | --- | --- |
| First setup appeared in one cut | A brief rail fill with an already-visible page settling into place | Give the infrequent welcome one authored moment |
| Forward and Back replaced the form instantly | Short direction-aware step transitions | Explain position without moving the anchored controls |
| Primary controls relied only on ripple | Subtle touch compression with unchanged touch geometry | Acknowledge a press while retaining native interaction |
| Set completion snapped green | Brief state transition, check response and success-only haptic | Confirm what was saved without delaying it |
| Navigation effects used separate timing | Shared timing/easing and a live system motion policy | Keep feedback consistent and respect accessibility choices |

The timings are 120 ms for presses, 180 ms for state, 220 ms for incoming setup steps and 280 ms for the first welcome. Exits are shorter. The pass adds no dependency, looping decoration, scroll reveal, animated input value or global page transition. Native chips, switches, dialogs and sheets keep their existing behavior.

The welcome begins only after the native starting surface is removed and the app window has focus. The launch background matches the app. Losing focus during the entrance settles it immediately; returning does not replay it.
