# Open Factor 0.8.1

Fitbod history import now resolves exercise names without a long manual-matching loop, and confirmation stays within reach for large exports.

## Fixes

- Automatically resolve clear compatible catalog names, common Fitbod vocabulary, reordered terms and a single bounded typo when the closest identity has a clear lead. Equipment and performed-metric compatibility are checked; ambiguous identities are not selected by popularity or arbitrary ordering.
- Preserve uncertain names as custom Weight/Reps exercises instead of blocking import, dropping sets or substituting an unrelated variant. These customs and their referencing history save atomically. Unused customs are not added, existing preserved identities are reused, and original source names remain in notes for review.
- Replace the expanded whole-history preview with compact, explicitly expandable workout summaries. Exercise choices can be reviewed/changed, kept under the original name or skipped. The acknowledgement, Import and Cancel actions are pinned above navigation instead of sitting below hundreds of workouts.
- Keep failures next to the fixed actions instead of burying them under the source-workout list. Show separate reading/matching progress, allow preparation to be cancelled and bound provider reads/matching to 30 seconds each. Cancel requests close the owned stream and cancel the provider open; late results cannot replace a newer preview. A provider returning zero bytes no longer spins without making progress. Failures/timeouts show an error rather than silently retrying.

Preserved custom exercises have no invented muscle targets or bodyweight contribution, so they remain unclassified in muscle-specific analytics. Review or change their catalog matching before saving if that classification is needed. Exact/closest matches are reviewable before saving. The separate XLSX program-target import retains its conservative unique-literal-match policy.

## Verification

- The supplied CSV resolves **all 59 names** against the real catalog: 13 normalized name/alias matches, 14 closest compatible matches and 32 preserved customs. No manual mapping is needed to retain its **290 workouts / 5,299 sets**.
- An isolated original-media Android API35 verification build selected the full CSV through Android's document picker, displayed the compact preview and completed the import. Private-store inspection compared every saved set's kilograms, reps, warm-up and completion against the source, confirmed unchanged non-history data and repeated the checks after an app restart. Private data and captures containing workout names are not published.
- The local debug and release JVM suites each recorded **245 cases: 244 passed, one optional private XLSX sample skipped, zero failures/errors**, with both explicitly supplied private Fitbod smoke cases enabled. New coverage includes safe matching, ambiguous/wrong-variant rejection, custom identity persistence/reuse/skips, zero-byte providers, cancellation and timeout behavior without retries.
- Local native API26 and API35 suites each recorded **62 JUnit cases: 61 passed, one optional external Health Connect provider test skipped, zero failures/errors**. New tests cover atomic custom/history persistence and reachable pinned acknowledgement/actions on a narrow, enlarged-text viewport. Runner console progress can include an extra lifecycle entry; counts here use JUnit XML.
- Debug and optimized release builds/lint passed. The first local release test process failed to connect to its Gradle worker; a fresh serial single-use Gradle run passed the full release suite. The local signed candidate passed signature and all 3,394 original-media manifest checks. Publication is gated by the complete source-mode main CI workflow and a separate original-media release build, release unit tests, lint, signature and asset checks. The attached receipts identify the exact APK; no pre-build APK hash is asserted here. Hosted tests do not receive the private CSV/XLSX, so their optional private-source cases skip.

These checks do not certify every movement match, arbitrary cloud-provider cancellation, TalkBack, every physical device or persistence fault injection. See the [import contract and limits](../FITBOD-IMPORT.md).

## Updating

Version **0.8.1 / code 17**, package `org.openfactor.app`, minimum Android 8.0 / API26. The existing signing identity and backup schema are unchanged. Export a complete backup before updating/importing. Nothing is automatically imported during the update.

Existing Fitbod workout IDs remain deduplicated and local edits are not overwritten. If a previous import intentionally skipped exercises, reimport does not fill them into those existing IDs; review the import contract before deleting or replacing any saved data. Original static media and on-demand video delivery remain unchanged.
