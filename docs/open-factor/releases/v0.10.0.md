# Open Factor 0.10.0

A typography refresh and stronger native foundations for reliable everyday logging. Open Factor remains a local-first Android app: no account, subscription, or new server dependency.

## Geist typography

- Bundle official Geist Sans for controls, body text and workout metrics, paired with regular Geist Serif for display headings.
- Define all Material typography roles, preserve readable numeric fields, and use Serif-specific leading without synthetic bold or italics.
- Keep the existing palettes and motion behavior. Fonts work offline; their OFL license and pinned provenance ship with the app.
- See [typography decisions and synthetic native captures](../TYPOGRAPHY.md).

## Reliability and recovery

- Surface storage-write failures with explicit retry for accepted pending edits or guidance to repeat a rejected action. Forms stay open, success-only navigation is skipped, and onboarding explains rejected saves locally.
- Preserve accepted typed edits after a synchronous action fails. No-op timers and lifecycle flushes cannot silently acknowledge a rejected-action warning.
- Keep workout completion owned outside the session screen so an outgoing screen or a later workout cannot consume the wrong completion.
- Reject stale automatic Health Connect results atomically after restore, manual sync or weight changes, without depending on a later screen update.
- Keep slow backup-provider writes outside the workout-command lock while retaining photos needed by the export snapshot. Preserve restore/checkpoint safety and authoritative notification ordering.
- Use typed destinations and validated saved navigation state. Start prerequisites are checked inside the same transaction as the change.

## Developer foundations

- Extract a feature-owned, Android-free JVM product core and verify real public consumption from a separate module.
- Add ownership/dependency enforcement and CI coverage. This is a JVM boundary, not a published Swift SDK or network API.
- Correct native journey fixtures for keyboard resizing and compact viewports without removing behavioral or animation assertions.

## Verification and limitations

- Implementation reviewed in two independent Astra High passes; reported findings addressed, including mounted onboarding storage-failure acceptance.
- Local core and independent-consumer suites each passed 17 tests. The app JVM suite recorded 331 tests with no failures/errors and one optional workbook-fixture skip. Python tooling recorded 37 tests, OK, with one optional public-baseline APK skip.
- The 70 selected native regressions passed on both API26 and API35 before release preparation. Font journeys passed at 100%, 135% and 200% on both APIs; API35 palette captures covered all five palettes in dark and light themes.
- Debug/test builds, Android lint, optimized unsigned source-mode release build, and source-mode content/font checks passed locally. Full hosted CI and the separate signed original-media release build remain publication gates for the exact release commit; attached generated receipts identify the actual APK.
- Native evidence uses synthetic fixtures on disposable emulators. Physical-device performance, comprehensive TalkBack/localization/tablet acceptance, and actual Health Connect permission/provider behavior are not established by these checks.

## Updating

Version **0.10.0 / code 20**, package `org.openfactor.app`, minimum Android 8.0 / API26. The package, persistent signing identity and public backup format are unchanged. The original static media pack is reused unchanged; videos remain streamed/cached, not bundled. No saved-schema migration or training-history rewrite is introduced.

**Export and retain a complete backup somewhere private before updating.** Install the signed APK over the existing app; do not uninstall first, because uninstalling removes local workouts and photos. A failed storage write can remain pending only while the app's owning process lives; no in-memory retry system guarantees recovery after process termination while storage is unwritable.
