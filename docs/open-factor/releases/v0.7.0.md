# Open Factor 0.7.0

A calmer dashboard, faster everyday logging, and reviewed local spreadsheet imports. This release also removes the unused upstream media-player projects from the repository.

## Changes

- Dashboard customization groups tiles into section cards with Edit, checkbox selection and contextual reorder/remove actions. Draft changes apply only on Save. Exercise search runs off the UI thread, and body-metric choices no longer build chart data.
- The Workout home weekly card emphasizes recorded working sets, labels its date range, and opens History from the whole card.
- Logger edits no longer serialize and rewrite unchanged saved workout history. History is stored in a separate atomic, checksum-verified archive; the live snapshot stays small. Current and startup-checkpoint history remain recoverable, and full exported backups stay self-contained.
- Finishing a workout and optionally saving its template is one durable background update with a saving state and retry error. Period summaries, exercise counts, catalog lookups and seven-day weight means avoid repeated scans.
- Large backups stream one workout and photo at a time during export, and restoration decodes the parsed metadata directly instead of duplicating the complete history through JSON strings/trees. This corrects a low-heap out-of-memory failure found by full CI after the earlier focused checks.
- Import actions reserve the larger of keyboard or floating/system-navigation clearance, rather than stacking both. Small-screen, enlarged-text tests verify the final targets and both actions remain reachable. The entry-point test also verifies that its real tap is clear of the floating navigation.
- A deterministic synthetic-backup generator and large-data regression tests support repeatable performance checks. The 2,000-workout fixture contains 48,000 working sets, 12,000 warmups and 2,000 weight readings.
- Removed 1,664 unused upstream entries: Nuvio media-player targets, bundled player libraries, legacy build/release/intake workflows and related tooling. Open Factor's app, media backend, current CI, licenses, attribution and release evidence remain.

## Spreadsheet import scope

Settings → **Import spreadsheet** supports the supplied phase-oriented XLSX layout: `Phase 1` / `Phase 2` / `Phase 3`, DAY sections and EXERCISE/WEEK/REPS/RIR columns. Each phase becomes an inactive manual program with weekly targets. Users explicitly choose the working-set count, resolve or skip exercise names, review omissions, and confirm the append. Existing programs, templates, drafts, active workouts and history are not replaced.

This is **not** a lossless or general-purpose spreadsheet importer:

- Numeric rep ranges, RIR and literal rest targets are retained. Weekly rows are not interpreted as set counts.
- AMRAP, seconds and steps are shown with warnings but remain blank numeric targets; their source labels are not persisted in program metadata.
- Weight, achieved reps, dates, difficulty/hidden-row rules, progression algorithms and videos are excluded. No completed history is invented.
- Formulas are never executed. Valid stored cached results may be used as data, with a stale-value warning.
- Unique normalized names/aliases can match automatically; ambiguous movement/equipment variants require explicit choices. The supplied workbook's actual-catalog preview required review of 33 of its 44 source names.
- CSV, XLS, encrypted files and other worksheet layouts are not supported.

See [the exact import contract and safety boundaries](../SPREADSHEET-IMPORT.md).

## Update and backup safety

The package and signing certificate are unchanged, supporting an in-place update from 0.6.2 and other releases with the same certificate. **Export and retain a full backup before updating.** Earlier testing alphas can use another key; see [the migration guidance](v0.2.0.md).

Old inline storage remains readable and moves to the new archive on the next save. A raw private preferences XML file alone is no longer a complete data copy; normal Export Backup includes all history and remains the supported transfer format. Archive integrity failures use the existing checkpoint/recovery flow rather than silently loading empty history. See [storage and performance details](../PERFORMANCE.md).

## Verification

- Debug and release variants each passed **213 JVM tests with zero skips**, including the explicitly supplied private workbook smoke test. The workbook itself and its extracted content are not included in the repository or verification bundle.
- Full local original-static-media device suites on API26 and API35 each recorded **56 JUnit test cases: 55 passed, one optional external Health Connect provider test skipped, zero failures/errors**. They cover the large backup round trip, streaming-writer bounds and escaping, photo attachments, storage/recovery/concurrency, small-screen import layout, native XML parsing, and existing workout journeys. Runner console progress can include an additional lifecycle entry; counts here use the JUnit XML cases.
- The existing main-branch source CI exposed two release blockers: a 192 MiB-heap large-backup OOM and a compact-screen import-entry assertion. This candidate removes duplicate backup JSON representations, streams export, corrects inset handling and strengthens the entry/layout tests rather than increasing the heap or skipping the tests. Source-mode GitHub CI is the publication gate; its completed run is linked from the GitHub release. The local API35 emulator's larger heap is not presented as proof of the 192 MiB CI case.
- The exact signed APK updated the downloaded, checksum-verified 0.6.2 APK in place on a disposable API26 emulator. A synthetic profile and saved 40 kg × 8 set survived. After exercising the first post-upgrade save, full pre/post-upgrade backup JSON was semantically identical and remained self-contained.
- The exact signed APK selected an authored synthetic one-day/two-week XLSX through the real picker, accepted an explicit count of three sets, reviewed and appended one inactive program, and exported it. The exported targets matched weeks 9/7 reps, 2/1 RIR and 120-second rest. Every non-program field remained unchanged. This is a small synthetic happy-path check, not a claim that all Outlift variants were chosen correctly.
- Earlier working-tree checks restored the 2,000-workout fixture into a separate Verification package and inspected Workout home and scrolling History. Those are operational and sampled storage checks, not physical-device frame-time benchmarks.
- Python tooling tests, source-APK integrity checks and the original-media verifier have separate receipts. Lint completed without errors; existing warnings remain.

The verification bundle contains selected synthetic native captures, artifact/signature receipts and test XML. It excludes signing material, private workbooks, real personal backups and imported source media. These checks do not certify every physical device, tablet, locale, accessibility setting, interrupted provider read, exercise variant or network condition. General-purpose spreadsheet conversion, TalkBack certification and physical-device frame pacing are not claimed.
