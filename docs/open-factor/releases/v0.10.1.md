# Open Factor 0.10.1

A maintenance release focused on safer media tooling, reproducible code-health checks and regression coverage. Everyday workout logging, the native design and the local-first data model are unchanged.

## App maintenance

- Reuse the shared name dialog for program-day renaming, with device tests for blank-name rejection, trimming and cancellation.
- Remove Kotlin-aware unused imports without deleting required Compose or JUnit wildcard imports.
- Keep the existing workout, backup and photo formats. No saved-schema migration or training-history rewrite is introduced.

## Safer media and developer tooling

- Reject incomplete or oversized licensed-preview downloads, including short responses that bounded HTTP reads previously accepted silently.
- Stage all preview downloads and attribution metadata before publishing. Controlled publication failures roll back prior bytes when filesystem recovery succeeds; incomplete rollback retains recovery files and reports an error. This is not a crash-atomic multi-file transaction.
- Reject symlinked source-asset parents during media staging and invalidate completed receipts during a failed pack refresh.
- Bound media conversion, verification and reference-tour subprocesses. Failed tour rebuilds cannot retain old completion indexes alongside partially replaced media; the new completion receipt is published last.
- Remove the offline-tooling import cycle and source-text `exec`, preserve import-safe command entry points and avoid repeated settings reads for the same Android namespace.
- Restore changed directory modes during offline-suite recovery. Reject directory ownership that cannot safely be preserved or recreated before deleting current file bytes; isolated filesystem tests cover mode changes, missing directories and failure boundaries.
- Bring onboarding smoke coverage in line with the current three-step profile setup, including Settings → Profile → Review setup, deferred drafts, validation, restart/resume, unrelated-record preservation and animation-setting restoration.
- Validate media-service index data at runtime and exercise S3 adapter contracts against a local test fixture, including ranges, checksums, bucket initialization and failure handling.

## Code-health CI

- Add independent pinned Desloppify snapshots for the Android project, main Python tooling and TypeScript media service, with logs and evidence uploaded from successful or failed scans.
- Fail on missing prerequisites, reduced/missing detector evidence, invalid snapshots, scanner failures and genuine TypeScript errors. Treat broader scanner findings as advisory rather than fabricating an unreviewed score threshold.
- Enforce focused Kotlin unused-import and Python import/undefined-name checks separately.
- Check the TypeScript adapter against the real locked compiler, including unused types/parameters/properties and mixed type errors, rather than relying on mocked exit codes.
- Document remaining style, structural and heuristic findings. This release does **not** claim every scanner finding is fixed or that subjective dimensions have been assessed. See [code-health scope and policy](../CODE-HEALTH.md).

## Verification and limitations

- Local core, independent-consumer and app JVM suites passed; the app suite retains its optional supplied-workbook skip. Python tooling, backend contracts, uploader contracts, TypeScript typechecking, focused native/Python lint, architecture verification and workflow syntax checks passed.
- Debug and optimized unsigned source-mode release builds and both Android lint variants passed for version 0.10.1/code 21. APK content checks verified 1,345 exercises, 44 licensed preview images and no private-reference entries.
- The shared-dialog/native regression suite was exercised on disposable API26 and API35 emulators before the release-version bump, with no failures and three environment-dependent skips per API. Those skips cover original-media guidance, an external Health Connect provider and opt-in recomposition evidence; optional fixture skips are not successful device/provider certification.
- The exact release commit must still pass hosted CI and the separate signed original-media publication build. Local source-mode checks do not establish real S3 deployment behavior, refreshed live-download behavior, physical-device performance, comprehensive accessibility/localization coverage or power-loss atomicity.

## Updating

Version **0.10.1 / code 21**, package `org.openfactor.app`, minimum Android 8.0 / API26. The package, persistent signing identity, backup format and original-media baseline are unchanged. Videos remain streamed/cached rather than bundled.

**Export and retain a complete backup somewhere private before updating.** Install the signed APK over the existing app; do not uninstall first, because uninstalling removes local workouts and photos.
