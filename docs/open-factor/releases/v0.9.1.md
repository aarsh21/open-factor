# Open Factor 0.9.1

A small bug-fix release for safer backups, more reliable workout editing and better navigation continuity. This is a patch to [0.9.0](v0.9.0.md), not a major feature release.

## Backups and data safety

- Reject malformed backup collections and program prescriptions instead of silently dropping records or changing numeric values. Missing legacy fields still use their compatibility defaults.
- Recover the last-good checkpoint when primary workout storage is missing, and serialize restore with other saved changes.
- Verify original progress-photo integrity during backup export. Reattaching the original repairs a damaged stored copy, and malformed UTF-8 backups are rejected rather than changing saved text.
- Show a privacy confirmation before exporting a complete backup: the file is not encrypted and includes original photos and image metadata.
- Correct the scoped User Profile export disclosure to list the saved fields already included: name, gender, height and weekly workout goal. Setup drafts remain excluded.

## Workout fixes

- Ask before converting saved Myo sets to warmups, since conversion removes additional component values on both sides. Cancel keeps the edit unchanged; history changes only after Save.
- Clear validation for effort fields removed by warmup conversion without clearing errors on remaining weight or reps fields.
- Allow valid deload targets up to 13 RIR in the target editor while keeping ordinary targets and recorded effort at their existing limits.
- Initialize new program Failure sets with zero RIR, consistently with the logger. Existing saved logs are not rewritten.
- Keep the current destination after activity recreation instead of replaying an old workout-notification intent.
- Order Recent workouts by their recorded dates rather than import or storage order.
- Reject formula-derived spreadsheet rest labels consistently with the literal-only import policy.

## Developer tooling

- Refuse unsafe media-staging output directories containing symlinks or invalid ownership manifests before cleanup can remove files.
- Add regression coverage for storage recovery, backups, workout editing, program targets, lifecycle behavior and staging safety. Update device-smoke flows for the export confirmation.

## Verification and limitations

- Local Python checks: **28 passed, one optional published-APK case skipped** because no baseline APK was supplied. Python/XML/shell syntax and whitespace checks passed.
- Android builds, JVM tests, device journeys and lint could not run locally because the Java/Android toolchain is unavailable. Candidate CI status is recorded in the pull request; these notes do not claim all Android checks have passed.
- Publication requires the complete main CI workflow, including API26/API35 device tests, to pass for the exact release commit. The separate original-media release build must also pass its unit tests, lint, signing-certificate and asset checks. Attached release receipts identify the actual APK; no pre-build hashes are asserted here.
- Photo-checkpoint recovery remains limited: a recovered checkpoint can reference originals deleted after that checkpoint. This release does not silently retain deleted photos.
- Physical-device performance, enlarged-text and TalkBack walkthroughs, provider failures, disk-full conditions and interrupted large backups remain outside this local verification.

## Updating

Version **0.9.1 / code 19**, package `org.openfactor.app`, minimum Android 8.0 / API26. The package and signing configuration are unchanged. There is no saved-schema, history-archive-layout or public-backup-format change; malformed data that was previously accepted through coercion is now rejected.

Export and keep a complete backup somewhere private before updating. Install the signed APK over the existing app; do not uninstall first, because uninstalling removes local training data and photos.
