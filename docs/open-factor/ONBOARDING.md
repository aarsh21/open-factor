# Setup and floating navigation

New installations open a welcome screen, then the three observed setup stages: **Basics → Gym & Equipment → Program**. Progress and partial input are saved locally. **Set up later** opens the app without discarding progress; **Settings → Set up Open Factor** resumes it. After completion, that Settings entry starts setup again with the existing profile. Upgrades and old backups continue to their existing dashboard.

Basics offers optional sync information, a local display name, workout weight units and optional height/body weight in centimeters/kilograms. Health Connect is explicitly unavailable and requests no permissions. The supplied source overview and optional-sync labels were observed; the complete intermediate source forms were not captured. The current profile form is a local reconstruction, and its height/weight values do not drive smart programming.

Choose the current gym, an equipment preset or a blank profile. The current gym retains its equipment/weights when renamed; a selected new preset becomes a separate default gym. Equipment and weight customization remain in Gym Profiles. Program setup opens the existing manual editor, preserving an existing draft, or can be deferred. Existing saved programs and workout history are retained. Smart generation, XLSX and source account sign-in remain outside this implementation.

The navigation capsule now overlays root scrolling content, with the page continuing behind and around it to the bottom edge. There is no full-width backing strip or reserved navigation viewport. Exercise search floats above the capsule; the list extends beneath both, with trailing scroll space so final items can be brought clear. Its bottom anchor and tab touch areas remain fixed. The shared selected surface moves between tabs; selected icons respond gently. Vertical root scrolling briefly shifts the capsule material by at most 2dp and changes its depth, returning to rest after scrolling. The touch targets do not drift with that visual response. System Remove animations disables the scroll response; Compose state animations follow Android animation scaling. No navigation is hidden while scrolling.

Source reference: privately retained welcome/three-stage screenshots and optional-sync XML. Source screenshot/XML timestamps differ and are not synchronized pairs. The attempted source pre-login check on the Android 15 emulator encountered its existing device-integrity error; no login, permission bypass or phone access followed. Full onboarding visual/behavioral parity remains open where source evidence is missing.
